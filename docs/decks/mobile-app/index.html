Today

The desk
is the chokepoint.

Sit down. Launch a job. Come back hours later to read the report. The agent's perception of the world is whatever CSV you uploaded — nothing else.

What changes about the agent
It's not a window onto the same agent.
It's a different agent.

One whose perception now includes situated, sensory, partial evidence — a photo of a gel, a voice memo, a geotag, a glance during a one-on-one, an uncertain question on the drive home.

The mobile app is less a client and more a sensor package.

16 / 17
What this is not

Not a port of the web UI.

The browser is right for
Sit down for 45 minutes. Launch a job. Read a report.
Focused, foreground, planned.
The phone is right for
Live your day. Occasionally observe, respond, glance.
Ambient, peripheral, situated.

Same backend. Two different products. The mobile one puts an autonomous research agent in the peripheral vision of a working scientist — which, ultimately, is where you want it.

Open questions

Decisions before we staff this.

Target user
Bench scientist, computational biologist, or field researcher? Different answers move different Phase-3 features up.
Push: ntfy.sh, or APNs/FCM?
ntfy is operationally simpler. APNs is better behaved and unlocks badges and Critical Alerts.
Repo shape
mobile/ directory in the existing repo, or a sibling openscientist-mobile repo?
Engineering ownership
A SwiftUI lead is a real hire — not a side project for the Python team.
Distribution
App Store, or TestFlight / enterprise only? Affects review surface for "agent that runs arbitrary code on uploaded data."
